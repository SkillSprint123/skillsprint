# Контракт нанофронтендов v1

Публичные экспорты — `src/index.ts`. Архитектура — `../../docs/architecture.md`.
Это внутренний контракт SkillSprint, отдельный от внешнего контракта BroJS.

- `schemas.ts` — Zod-схемы модуля, экземпляра, контекста, пользователя и реестра.
- `types.ts` — типы через `z.infer`; нет отдельно написанных копий интерфейсов.
- `validation.ts` — assert-проверки на границе загрузки.

Модуль экспортирует `contractVersion: 1` и `mount(element, context)`.
Результат — экземпляр с `unmount()`. Поддерживаются асинхронные mount/unmount.
Реестр сохраняет `schemaVersion: 1` и точные версии модулей. Поле `styles`
сохранено: для CSS-in-JS-модулей используется `[]`.

`assertNanoModule` и `assertNanoInstance` проверяют форму через Zod, сохраняя
исходные функции и их `this`. Для callable-экспортов проверяются наличие и тип
функции; загрузчик отдельно проверяет контекст до mount и экземпляр после mount.
Это не выполняет модуль и не доказывает корректность его бизнес-логики.
`assertNanoRegistry` проверяет реестр; `assertNanoContext` — переданный контекст.
Загрузчик находится в `../nano-runtime/src`.

DOM принадлежит модулю только внутри переданного контейнера. Навигацию задаёт
корень. React/Vue и внутренние store не пересекают контракт. `unmount` очищает
DOM, CSS-in-JS style-теги, подписки, таймеры и сетевые соединения. `entry` и
`styles` разрешаются относительно URL реестра. Несовместимое изменение требует
новой версии контракта.

Каталог остаётся источником контрактов в корневом репозитории. Подготовлен
пакет `@skillsprint/contracts@1.0.0` с CommonJS JS, TypeScript-декларациями и
публичными экспортами v1. `npm run contracts:build` собирает `dist`,
`npm run contracts:pack` из корня создаёт `.artifacts/skillsprint-contracts-1.0.0.tgz`.
Сгенерированные файлы в Git не включаются.

Пакет во внешний npm-реестр пока не опубликован. Для четырёх отдельных
репозиториев нужно согласовать постоянный источник установки, доступный
`npm ci` в Jenkins. Нано фиксируют версию пакета и не создают копии схем.
Порядок подключения описан в `../../docs/integration.md`.
