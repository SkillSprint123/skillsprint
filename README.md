# SkillSprint

Сервис подготовки к собеседованиям: план занятий, тренажёр вопросов,
AI-собеседование и прогресс. Команда — 3–4 человека, по полезной фиче на участника.

## Текущая основа

- React 18 + TypeScript, React Router 6, CSS-in-JS через Goober.
- Корневой микрофронтенд BroJS 2 с текущей Webpack-сборкой.
- Контракт v1 в `packages/contracts`: Zod-схемы и отдельные типы через `z.infer`.
- Загрузчик `packages/nano-runtime`: проверка реестра, ESM-модули по URL,
  mount/unmount, таймауты, ошибки и очистка при смене разделов.
- Express для серверного API и проверки работоспособности.
- Redux Toolkit / RTK Query и SDK GigaChat предусмотрены в соответствующих
  модулях; неиспользуемые зависимости в корне не устанавливаются.
- Unit-тесты через `node:test`, ESLint, отдельная проверка типов, Jenkins.

Chakra UI, Emotion, Framer Motion и старый генератор товарных карточек удалены.
Корень показывает обзор, подключает нано по реестру и отображает отсутствие
модуля, пока его источник не задан. Четыре бизнес-нано, хранение данных,
AI-агент и оплата ещё не реализованы. В корне есть страница трёх демонстрационных тарифов.

Общая оболочка сверена с макетом Figma: боковое меню, логотип, верхняя строка
с текущей датой и подпись внизу. Иконки и Inter хранятся локально, стили
принадлежат контейнеру подключения. В корне есть локальный аккаунт и быстрый вход;
демонстрационная серия занятий из макета не выдаётся за реальные данные.
На старте обзор предлагает переходы в разделы. Карточки цели, задач и статистики
из Figma требуют данных нанофронтендов и пока не реализованы.

## Запуск

Node.js 22, npm. Рекомендуемая версия Node зафиксирована в `.nvmrc`.

```sh
npm ci
npm start
```

Приложение: `http://localhost:8099/skillsprint`. Проверка локального API:
`GET http://localhost:8099/api/health`.

Чтобы видеть корень и локальный interview вместе, установите зависимости
в соседнем проекте `../skillsprint-ai` (`npm ci`), затем из корня выполните:

```sh
npm run start:all
```

Команда запускает оба dev-сервера и подключает interview через
`config/nanos.dev.json`. Откройте `http://localhost:8099/skillsprint` и выберите
«AI-собеседование». Порты 8099 и 5173 должны быть свободны; ранее запущенный
`npm start` нужно остановить. `Ctrl+C` завершает оба сервера. Изменения исходников
обрабатываются dev-серверами. Если interview лежит в другой папке, задайте
`INTERVIEW_DIR=/путь/к/проекту npm run start:all`.

```sh
npm run check       # типы, ESLint, unit-тесты
npm run build:prod  # микрофронтенд BroJS в dist
npm run build:integrated # корень и настроенные нано; нужен доступ к их Git-источникам
npm run build:release # полный выпуск; нужны Git-источники всех четырёх нано
npm run prom        # SPA-оболочка brojs compile + локальный prom-server
npm run contracts:pack # архив общего пакета контрактов в .artifacts
```

## Аккаунт и быстрый вход

При первом открытии приложение показывает `/skillsprint/login`; регистрация —
`/skillsprint/register`, профиль — `/skillsprint/account`. Кнопка входа всегда
открывает приложение, даже с пустыми или произвольными логином и паролем.
Пароль не передаётся адаптеру и не сохраняется. Это локальный деморежим,
серверной проверки учётных данных и защиты API пока нет.

Профиль позволяет сохранить имя, почту, направление, уровень, цель и цвет
аватара. Данные и сессия хранятся в localStorage этого браузера. Выход завершает
сессию и сохраняет профиль для следующего входа; обновление страницы не требует
повторного входа. Между вкладками синхронизируются изменения и выход.
Если хранилище недоступно, приложение работает в памяти текущей вкладки.
Нано получают `{ id, displayName }` через `NanoContext.user`; общий store не создаётся.

Переход в аккаунт находится в нижнем блоке профиля боковой панели; он доступен
и на мобильном экране. Страница `/skillsprint/pro` показывает три демонстрационных
тарифа: Бесплатный (0 ₽), Pro (790 ₽/месяц) и Ultimate (9 990 ₽/месяц).
Переходы есть в баннере обзора и карточке тарифа в аккаунте. Выбор сохраняется
локально, без оплаты и включения платных возможностей. Цены и состав тарифов —
пример для демонстрации, они не утверждены. Старые профили получают бесплатный
тариф без потери данных или сессии.

## Проверки перед коммитом и push

Git-хуки Husky устанавливаются автоматически при `npm install` / `npm ci`.
Если Git был создан после установки зависимостей, выполните `npm run prepare`.
Перед коммитом запускается `npm run check`: Prettier, типы, ESLint и все тесты.
Перед push повторяются проверки и выполняется production-сборка корня без
получения внешних нано. При ошибке коммит или push останавливается.
Проверки не изменяют файлы автоматически.

```sh
npm run format:check # проверить форматирование
npm run format       # исправить форматирование
npm run lint         # запустить ESLint
npm run lint:fix     # исправить доступные ESLint-ошибки
npm run test:all     # unit-тесты и проверки сборки выпуска
npm run check        # все проверки без сборки приложения
```

После исправления файлов добавьте изменения заново через `git add` перед
коммитом. Форматированием управляет Prettier; конфликтующие правила ESLint
отключены через `eslint-config-prettier`. Сборки, кэши и архивные материалы
дизайна исключены из форматирования. Jenkins выполняет тот же `check`, а
установку локальных Git-хуков пропускает через `HUSKY=0`.

`brojs compile` создаёт локальную SPA-оболочку; публикация на внешний стенд
использует микрофронтенд, полученный через `brojs build`.
Npm-команды запускают BroJS через `scripts/brojs.mjs`: сообщения сборки,
серверов, проверок и Jenkins выводятся на английском. Обёртка переводит
сообщения установленного BroJS 2 без правки `node_modules`, сохраняет
диагностику и коды завершения. Прямой запуск `brojs` использует язык пакета.

## Конфигурация и секреты

`bro.config.js` подключает `server/api` и задаёт навигацию `skillsprint.main`, API `skillsprint.api`
и feature toggle `skillsprint → ai-interview → value`. AI по умолчанию выключен.
На стенде эти значения предоставляет BroJS, локально — `bro.config.js`.
Если включение фичи в панели недоступно, во вкладке «Конфиг» задайте префикс
`skillsprint`, ключ `ai-interview`, значение `true`. Непустая конфигурация
`skillsprint.ai-interview` имеет приоритет над фичей; значение `false`
выключает раздел. Пустое или отсутствующее значение оставляет управление фиче.
Флаг отражает доступность раздела; он не заменяет серверные лимиты доступа.

`.env.example` содержит будущие серверные параметры GigaChat. Ключи не нужны
для запуска текущего каркаса. При реализации сервера переменные нужно загрузить
из окружения; файл `.env` нельзя включать в Git или клиентский bundle.

## Архитектура и команда

Инструкции агенту: `AGENTS.md`.
Согласованные решения и ограничения: `docs/architecture.md`.
Дерево папок и правила размещения файлов: `docs/structure.md`.
Стек, распределение фич, требования и следующий этап: `docs/stack.md`.
Контракт подключения: `packages/contracts/README.md`.
Подключение репозиториев, сборка и Jenkins: `docs/integration.md`.
Материалы существующего дизайна: `design/figma-repair`.

Корень разделён на `src/app`, `src/pages` и `src/shared`, API — `server/api`.
Схемы и типы расположены рядом в `schemas.ts` и `types.ts`.
Стили компонентов находятся в `styles.ts`, обычных CSS-файлов в приложении нет.
Для исходников выбраны пять репозиториев: `skillsprint` для корня и по одному
для learning-plan, trainer, interview и progress. У нанос будут свои зависимости,
локальный запуск, проверки и сборка; корень подключает собранные модули через
контракт v1. Публикация на стенд остаётся общей. Загрузчик, получение исходников
и формирование общего артефакта реализованы. Для interview задан Git-источник,
для остальных трёх нанос источники пока не заданы. Interview закреплён на commit SHA,
получается по публичному HTTPS и собирается как ESM через `build:nano`.
Переход корня на Vite остаётся отдельной задачей.
Нанофронтенды не используют общий Redux-store и не импортируют внутренний код
друг друга.

## CI и публикация

GitHub Actions: `.github/workflows/ci.yml` запускается при push в `main`,
для pull request и вручную через вкладку Actions. На Node.js из `.nvmrc`
выполняются `npm ci`, `npm run check` и `npm run build:prod`.
Workflow проверяет и собирает корень с настроенными нанос; автоматическая
публикация на стенд в него не входит.

Пять репозиториев объединяются в GitHub Organization или GitLab Group.
Получение исходников поддерживает SSH и HTTPS Git и не привязано к одному
хостингу. Для публичного HTTPS-источника interview SSH-ключ и `known_hosts`
не требуются. Параметры отдельного Jenkins pipeline для SSH:
`GIT_SSH_CREDENTIALS`, `GIT_KNOWN_HOSTS`.

`Jenkinsfile`: `npm ci` → типы → lint → тесты → production-сборка → архивация
`dist/**`. По умолчанию собирается корень с настроенными нанос.
`build:prod` вызывает `build:integrated` и требует доступа к внешним
репозиториям. Локальная SPA-компиляция не получает нано.
`build:integrated` получает, проверяет и собирает только настроенные
нано, затем объединяет их с корнем. `build:bundle` — внутренний шаг сборки
BroJS без формирования общего артефакта.
`FULL_RELEASE=true` получает все четыре Git-источника на фиксированных refs,
проверяет и собирает их, затем создаёт один общий артефакт. Состав выпуска
настраивается в `config/nano-sources.json`; `source: null` — честная заглушка.
`npm run build:release` требует все четыре Git-источника и останавливается
при неполной конфигурации. Сборки и служебные checkout-каталоги не входят в Git.

Публикацию на стенд нужно добавить после получения команды деплоя и реквизитов;
сейчас Pipeline не проверен на настоящем Jenkins, автоматический деплой не
настроен. Интеграцию настоящих React/Vue-модулей и стенда нужно проверить
после получения соответствующих модулей и доступа.
GitHub Actions начнёт выполнять проверки после загрузки workflow в репозиторий
на GitHub; для Jenkins отдельно требуется подключение сервера.
Создание Git и загрузка изменений остаются за владельцем проекта.
