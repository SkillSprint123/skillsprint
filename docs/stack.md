# Стек и границы SkillSprint

Обновлено 24 октября 2026 года. Архитектурный источник — `architecture.md`.

## Выбранный стек

| Область              | Решение                                                           | Назначение                                                           |
| -------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------- |
| Корень               | React 18 + TypeScript 5, strict                                   | Оболочка и интеграция со стендом                                     |
| Сборка корня         | BroJS 2 / существующий Webpack                                    | Сохранить загрузку внешним fire.app                                  |
| Маршруты             | React Router 6                                                    | Обзор, план, тренажёр, интервью, прогресс, Pro                       |
| Стили React/Vue      | Goober, CSS-in-JS в `styles.ts`                                   | Генерируемые классы и style-тег внутри контейнера модуля             |
| Состояние React-нано | Redux Toolkit, RTK Query                                          | Store и API конкретной фичи                                          |
| Vue-нано             | Vue 3 + Vite, локальное состояние                                 | Допустимый независимый стек участника                                |
| Контракты            | Zod-схемы + `z.infer` в отдельных `types.ts`, v1                  | DOM-контейнер, контекст, mount/unmount                               |
| API                  | Node.js 22 + Express                                              | Валидация, серверные лимиты, работа с AI                             |
| Валидация и типы     | Zod 3, TypeScript `z.infer`                                       | Сейчас config, разделы, контракты, health API; далее формы и payload |
| AI                   | Официальный `gigachat` JS SDK                                     | Серверный доступ к GigaChat, без ключей в браузере                   |
| Unit-тесты           | `node:test` + `node:assert`, компиляция TypeScript                | Логика, контракты, конфигурация                                      |
| Проверки             | ESLint + `tsc --noEmit`                                           | Качество и типобезопасность                                          |
| CI                   | Jenkins, Node.js 22                                               | Проверки, production-сборка, архив артефакта                         |
| Версии               | package.json, версия каждого нано, contractVersion, schemaVersion | Явный состав выпуска                                                 |
| Features/config      | API BroJS и `bro.config.js`                                       | Включение AI, базовые адреса и навигация                             |

Версии React и React Router сохранены из существующего проекта; обновление
на новый major не входит в очистку. Зависимости Vue/Vite будут добавлены
в конкретный нанофронтенд при его создании. Корень пока не переведён на Vite.
Redux устанавливается в React-нано, которому нужно это состояние; корень
не создаёт общий store и не содержит неиспользуемых Redux-зависимостей.
В корне реализован локальный аккаунт: вход и регистрация без проверки пароля,
редактирование профиля, сохранение сессии и выход. Данные проверяются Zod и
сохраняются в localStorage. База данных и серверная аутентификация ещё не
выбраны; позже локальный адаптер нужно заменить согласованным API.
Клиентское хранилище не подходит для защиты платных лимитов.

## Фичи команды

| Участник | Нанофронтенд  | Полезный сценарий и результат                                           |
| -------- | ------------- | ----------------------------------------------------------------------- |
| 1        | learning-plan | Задать роль, срок и темы; получить задачи на день и отметить выполнение |
| 2        | trainer       | Ответить на вопрос; посмотреть эталон, ошибки и темы для повторения     |
| 3        | interview     | Пройти AI-сессию; получить вопросы по цели и разбор ответов             |
| 4        | progress      | Увидеть историю занятий, изменение результатов и слабые темы            |

При трёх участниках progress можно объединить с learning-plan. Корень,
контракты и интеграционные проверки — общая ответственность команды.
Выбраны пять репозиториев: `skillsprint` для корня и четыре отдельных для нанос
(названия приведены в `architecture.md`). Каждый нано имеет собственный цикл
разработки, проверок и сборки. Общий выпуск получает конкретные версии сборок
для общего артефакта корня. Получение и сборка реализованы; Git-источник пока
задан только для interview, его сборка ещё не проверена. Настоящий Jenkins
и публикация на стенд ещё не проверены.
Модули передают согласованные данные через API/контекст/события, а не store.
Доменные payload и события потребуется согласовать отдельно; текущий контракт
подключения не задаёт структуру плана или оценки ответа.

## AI-агент

Нужен агентский сценарий, а не единственный вызов «ответь на сообщение»:

1. Получить цель подготовки и доступные темы через серверный инструмент.
2. Выбрать вопрос с учётом предыдущих ошибок.
3. Оценить ответ по критериям и решить, нужен ли уточняющий вопрос.
4. Сохранить результат через инструмент и предложить задачи на повторение.
5. Завершить сессию с отчётом.

Предлагаемые инструменты: `getPreparationGoal`, `getWeakTopics`,
`recordInterviewAnswer`, `suggestPlanTasks`. Их схемы и разрешённые действия
реализует сервер. Изменения плана показываются пользователю как предложение.
Оркестрация — ограниченный цикл с лимитом шагов и вызовами функций GigaChat;
LangChain и сторонние LLM-провайдеры для первой версии не нужны.
API сессии, таймауты, хранение и лимиты будут реализованы в interview.

Документация провайдера:

- [GigaChat REST API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)
- [API и SDK](https://developers.sber.ru/docs/ru/gigachat/api/main)

Адрес и модель задаются серверным окружением. SDK будет установлен в серверный
модуль при реализации интеграции; авторизация и доступ к настоящему API ещё
не проверены. TLS проверяется;
для необходимых сертификатов используется доверенный CA, а не `rejectUnauthorized: false`.

## Монетизация

Бесплатный тариф — ограниченное число AI-сессий; Pro — расширенный лимит
и подробная аналитика. Для курсового: экран тарифа, видимый остаток лимита,
сообщение об исчерпании и демонстрационный переход на Pro с явной отметкой.
Реальная оплата не нужна. В корне реализована демонстрация трёх тарифов: Бесплатный,
Pro (790 ₽/месяц) и Ultimate (9 990 ₽/месяц). Выбор сохраняется в аккаунте локально
и не включает платные функции. Количество сессий и реальные цены пока не утверждены.

## Следующая реализация

`nano-runtime`, контейнер и общий процесс сборки артефакта реализованы.
Тесты проверяют подключение, асинхронную смену разделов, unmount,
версии и формирование реестра. Далее создать функциональные модули в четырёх
репозиториях, подключить их через `config/nano-sources.json` и проверить Vue-нано,
ресурсы и общий выпуск на настоящем стенде. Инструкция — `integration.md`.
Перенос корня на Vite выполняется
отдельной задачей, как закреплено в `docs/architecture.md`.

## Размещение типов и стилей

Подробная структура — `structure.md`. Данные описываются один раз в Zod-схеме,
типы выводятся из неё в отдельном `types.ts`. TypeScript продолжает проверять
код, Zod проверяет данные во время выполнения. Типы React/DOM/Goober берутся
из соответствующих библиотек. CSS-in-JS применяется ко всем новым модулям:
React-компоненты используют `StyleScope`, Vue-адаптер связывает `css` с собственным
контейнером и удаляет созданный style-тег в `unmount`. Нет глобального reset.

Выбран [Goober css API](https://github.com/cristianbote/goober#csstaggedtemplate)
с объектами стилей и привязкой к target. Chakra UI и Emotion не возвращаются.
Файлы и inline-стили архивного Figma-плагина в `design/` не являются частью
приложения и сохраняются как материалы дизайна.
