# Подключение четырёх репозиториев к SkillSprint

Корень готовит один общий артефакт для одного поддомена. Внешний формат BroJS
и Webpack сохранён. Git-источник interview задан в конфигурации; остальные
три источника ещё не заданы. Interview закреплён на commit SHA и собирается
командой `build:nano` в `dist-nano`; репозиторий получается по публичному HTTPS.

## Что работает сейчас

- Маршруты `/plan`, `/trainer`, `/interview`, `/progress` подключают нано по
  реестру; обзор и Pro принадлежат корню. Вложенные маршруты нано поддерживаются.
- Реестр и экспорты проверяются контрактом v1. Корень передаёт DOM-контейнер,
  `basePath`, `apiBaseUrl`, `navigate` и `user: null` до появления авторизации.
- Загрузка, отсутствие модуля, ошибка и повторная попытка имеют отдельные
  состояния. Таймаут подключения — 15 секунд. Уход во время асинхронного mount
  отсоединяет его контейнер и отключает поздно полученный экземпляр.
- Goober-стили и DOM каждого нано должны находиться в его контейнере.
- `npm run build:prod` вызывает `build:integrated` и включает настроенные нано.
  Нужен сетевой доступ к их Git-источникам и npm-зависимостям.
- `npm run build:integrated` получает и собирает настроенные нано, затем корень
  и общий артефакт. Источники со значением `null` пропускаются с сообщением.
- `npm run build:release` требует Git-источники всех четырёх нанос, получает
  их фиксированные версии, выполняет проверки и собирает полный выпуск.

## Конфигурация вместо правок загрузчика

`config/nano-sources.json` — состав выпуска для CI. Для каждого из четырёх
модулей уже есть запись. Когда репозиторий появится, замените только его
`source: null`, например:

```json
{
  "version": "0.1.0",
  "source": {
    "kind": "git",
    "url": "git@git.example.com:skillsprint-team/skillsprint-trainer.git",
    "ref": "refs/tags/v0.1.0"
  },
  "scripts": { "check": "check", "build": "build:prod" },
  "output": "dist",
  "entry": "index.js",
  "styles": []
}
```

Это пример записи, а не подтверждение существования репозитория или тега.
`git.example.com` заменяется настоящим SSH-хостом, а путь — путём репозитория.
Источники поддерживают SSH и HTTPS-адреса GitHub, GitLab и других Git-хостингов.
Для публичного репозитория можно указать
`https://github.com/SkillSprint123/skillsprint-Interview.git` без SSH-ключа
и `known_hosts`. Пароли и токены в URL не допускаются; HTTP не поддерживается.
Вместо тега можно указать полный commit SHA (40 символов). `main` и `latest`
не принимаются. Релизные теги нельзя перемещать; для строгой фиксации используйте
SHA. Версия в `package.json` нано должна совпадать с `version` конфигурации.
`scripts` — названия npm-скриптов, а не произвольные shell-команды.

`output` — каталог результата внутри полученного репозитория. `entry` и
`styles` — пути внутри этого каталога. Копируется весь каталог, включая
чанки, изображения и шрифты. Символические ссылки, выходы за каталог и файлы
секретов вроде `.env`/`.npmrc`/приватных ключей запрещены.

Получение Git-исходников выполняется в `.nano-work/checkouts/<id>`. Эти каталоги
служебные и могут быть пересозданы. Все нано проходят `npm ci`, проверку и
сборку. При ошибке работа останавливается; старый lock источников удаляется.
После сборки корня сборки нано копируются в `dist/nanos/<id>/<version>/`.
`release.json` содержит версии и фактические commit SHA для проверки выпуска.

`nanos.json` — другой файл: его генерирует сборка, читает браузер. В нём только
`schemaVersion`, версии модулей, `contractVersion`, `entry` и `styles`; адреса
Git и команды сборки браузеру не передаются. Формат контракта v1 сохранён.

## Локальная проверка

```sh
npm ci
npm run check
npm run build:prod
npm start
```

В production-артефакте присутствуют настроенные модули. Локальный `npm start`
использует dev-реестр, задаваемый ниже. AI-собеседование по умолчанию отключено
флагом BroJS.

Для работы с настоящим dev-сервером нано заполните `config/nanos.dev.json`
по схеме реестра v1: `entry` может указывать на HTTP-адрес ESM-модуля локального
dev-сервера. Затем:

```sh
NANO_REGISTRY_FILE=config/nanos.dev.json npm start
```

Webpack отдаёт этот реестр рядом с bundle и отслеживает изменения файла.
Dev-сервер нано должен разрешать CORS для origin корня. Запускайте один
локальный сервер корня за раз: команды используют порт 8099.

## Общий пакет контрактов

```sh
npm run contracts:pack
```

Результат: `.artifacts/skillsprint-contracts-1.0.0.tgz`, содержащий JS,
декларации типов и публичные экспорты v1. Для локальной проверки пакет можно
установить из архива. Для независимого `npm ci` в Jenkins понадобится доступный
команде npm-реестр или постоянный URL архива, зафиксированный в зависимостях и
lock-файле каждого нано. Абсолютный путь к архиву на личном Mac для CI не подходит.
Пакет подготовлен, но во внешний реестр не опубликован.

Нано экспортирует именованные `contractVersion = 1` и `mount(element, context)`;
mount возвращает экземпляр с `unmount()`. Фреймворк включается в ESM-сборку нано,
если совместное использование зависимостей отдельно не согласовано. Не должно
быть неразрешённых браузером импортов вроде `import ... from 'react'` в готовом
артефакте. При ошибке mount модуль сам освобождает уже созданные ресурсы.

## Jenkins и стенд

Штатный pipeline стенда из предоставленного лога получает репозиторий корня
по HTTPS и запускает `VERSION=main npm run build:prod`. Он использует скрипты
стенда, а не `Jenkinsfile` этого репозитория. Interview также получается по HTTPS,
поэтому для текущей публичной связки SSH-настройки контейнера не требуются.
Ошибка `Host key verification failed` относится к SSH-подключению; проверку
host key отключать не нужно.

Следующие параметры относятся к отдельному pipeline из нашего `Jenkinsfile`.
Подключите `Jenkinsfile` из корневого репозитория через Pipeline from SCM.
Нужны Git, Pipeline, Docker Pipeline, Credentials Binding и SSH Agent plugins,
а также агент с Docker. Node.js в контейнере — 22.

По умолчанию `FULL_RELEASE=false`: проверяется и архивируется корень
с настроенными модулями (`build:prod`).
Получение исходников, проверки и сборка выполняются одной командой.
Для общего выпуска заполните четыре источника, включите
`FULL_RELEASE` и задайте:

- `GIT_SSH_CREDENTIALS` — ID SSH-учётных данных Jenkins с правом чтения
  репозиториев нанос; доступ к корневому SCM настраивается в самой задаче.
- `GIT_KNOWN_HOSTS` — ID Secret file с проверенными SSH host keys выбранного
  Git-хостинга. Проверка host key не отключается.

Pipeline устанавливает зависимости корня, проверяет его, затем получает,
проверяет и собирает четыре нано, собирает корень и общий `dist`, архивирует
результат только после успеха. Неполный выпуск в режиме FULL_RELEASE завершается
ошибкой. Сам Pipeline пока не запускался на вашем Jenkins.

Архивация `dist/**` в Jenkins не публикует сайт. Шаг публикации нужно подключить
по инструкции владельца стенда. Сервер должен отдавать весь артефакт, включая
вложенные каталоги, с корректным MIME для JS и JSON. По умолчанию ресурсы имеют
адреса `/static/skillsprint/<версия-корня>/...` на том же origin, что и приложение.
Значение BroJS-конфигурации `skillsprint.nanos` может задать другой URL реестра;
пустое значение выбирает реестр рядом с текущим bundle. Локально его можно
переопределить переменной `NANO_REGISTRY_URL`.

Новый каталог версии сначала загружается полностью, затем переключается версия
корня в стенде. Опубликованные версии не перезаписываются. Для отката выбирается
предыдущий общий выпуск. Секреты API GigaChat остаются в окружении сервера.

## Что ещё нужно от команды

Четыре реальные ESM-сборки с контрактом v1 и npm-скриптами, фиксированные refs,
источник пакета контрактов, Jenkins Credentials и инструкция публикации на стенд.
Функциональные нано, авторизация, AI-агент, DNS/HTTPS и настоящий деплой не
созданы этой подготовкой корня. Совместимость React проверяется локально; Vue
и настоящий внешний fire.app нужно проверить при получении соответствующего
модуля и доступа к стенду.
