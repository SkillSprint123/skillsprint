# Структура проекта

В корне остаются конфигурация сборки, npm-команды, `AGENTS.md` и `README.md`.
Приложение, сервер, общие контракты, тесты и документация разделены:

```text
SkillSprint/
├── src/
│   ├── index.tsx                    # публичные экспорты BroJS
│   ├── app/
│   │   ├── App.tsx                  # корневые провайдеры
│   │   ├── entry/                   # внешний mount/unmount
│   │   ├── config/                  # BroJS config, Zod-схемы и парсер
│   │   ├── router/                  # маршруты и описание разделов
│   │   └── shell/                   # меню и раскладка приложения
│   ├── pages/
│   │   ├── overview/                # обзор
│   │   ├── nano/                    # контейнер нано, загрузка/ошибки/повтор
│   │   ├── section/                 # заготовка Pro и выключенный AI-раздел
│   │   └── not-found/               # неизвестный маршрут
│   └── shared/
│       ├── styles/                  # CSS-in-JS scope, токены и общие стили
│       └── types/                   # декларации для ресурсов
├── server/api/                      # Express Router, серверные схемы/типы
├── packages/contracts/src/          # независимый контракт подключения v1
├── packages/nano-runtime/src/       # загрузчик и жизненный цикл нано
├── config/                         # состав выпуска и Zod-схемы для CI
├── tests/unit/                      # unit-тесты логики и схем
├── tests/release/                   # сборка артефакта, получение sources, ошибки CI
├── scripts/release/                 # получение исходников и общий артефакт
├── scripts/                         # упаковка контрактов, Webpack plugin
├── docs/
│   ├── architecture.md              # согласованная архитектура и её ограничения
│   ├── stack.md                     # технологии и продуктовые фичи
│   ├── structure.md                 # этот документ
│   └── integration.md               # подключение репозиториев и выпуск
├── design/                          # исходные материалы дизайна
├── AGENTS.md                        # единственный файл инструкций агенту
└── README.md                        # запуск и статус проекта
```

## Где хранить файлы

- Компонент и его `styles.ts` лежат рядом в папке своей страницы или оболочки.
- `schemas.ts` содержит Zod-схемы данных. `types.ts` содержит `z.infer` от этих
  схем. Дублирующие интерфейсы и inline-типы props не добавляются.
- Типы React/DOM/Goober берутся из библиотек и при необходимости именуются в
  локальном `types.ts`: Zod не заменяет типы платформенных API.
- Общие значения цветов/размеров — `src/shared/styles/tokens.ts`.
- `StyleScope` привязывает Goober к DOM-контейнеру подключения. После unmount
  style-тег удаляется вместе с контейнером; чужой head не очищается.
- `src/index.tsx` — только фасад внешнего контракта. Его экспорты не меняются
  при перестановке внутренних папок.
- `packages/contracts/src/index.ts` — публичный фасад v1; `schemas.ts`,
  `types.ts`, `validation.ts` разделяют схемы, типы и runtime-проверки.
- Express сейчас использует CommonJS, как ожидает BroJS. Серверные схемы
  находятся в `schemas.js`, типы — в `types.ts` через `z.infer`; JS проверяется
  TypeScript с `allowJs` и `checkJs`. Серверные файлы не импортируются в клиент.
- Тесты находятся в `tests/unit`, а не перемешаны с production-кодом.
- `design/figma-repair` — архив материалов Figma-плагина, не код приложения.

## Что будет позже

Рабочие модули learning-plan, trainer, interview и progress ещё не созданы.
Они будут разрабатываться в четырёх отдельных репозиториях
`skillsprint-learning-plan`, `skillsprint-trainer`, `skillsprint-interview` и
`skillsprint-progress`. Текущий репозиторий `skillsprint` содержит корень,
контракты и загрузчик; общая workspace-структура `apps/*` не планируется.
Подключение собранных нанос и формирование общего артефакта реализованы;
реальные Git-источники и публикация на стенд пока не настроены.
Переход на Vite остаётся отдельной задачей.

Служебные каталоги `.nano-work`, `.brojs`, `.artifacts`, `.test-dist` и любые
`dist` исключены из Git. Реестр `nanos.json` и сведения о выпуске `release.json`
генерируются внутри итогового `dist`, а в Git хранится `config/nano-sources.json`.

Раньше `agent.md` хранил архитектуру, а `AGENTS.md` — короткие правила агента.
Теперь инструкции находятся только в `AGENTS.md`; архитектура перенесена
в `docs/architecture.md` без потери решений о версиях, реестре и жизненном цикле.
